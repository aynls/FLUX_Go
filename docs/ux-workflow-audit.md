# 创作工作流与交互设计审计

2026-10-07。用户的典型工作流是用一套提示词批量生成候选图，挑选其中一张，再使用适合编辑的模型继续创作。当前界面主要按模型家族组织独立草稿，每个家族又始终占用中央画布。用户围绕图片推进任务，界面却要求用户围绕模型寻找状态；这是导航反直觉的主要原因。

本轮完成生成记录面板的折叠与缩略图高度修复，以及 Nano Banana 2.1 接入。用户随后明确引入图库：本机和剪贴板导入的图片复制到图库目录，所有生成结果自动进入图库，图库删除同时删除对应文件和数据项，图库内容可以方便地加入当前任务成为参考素材。项目尚未发布，迭代允许重写，无需旧版本兼容和旧数据迁移。以下图库、导航、素材导入和工作流方案尚未实现。问题依据当前源码、浏览器布局检查和模拟交互复现；没有执行真实付费生成。

## 当前交互中的断点

| 操作与实际行为 | 对创作的影响 | 代码位置 |
| --- | --- | --- |
| 结果开始编辑后切换模型家族，会进入另一个家族的编辑草稿；所选图片不会随之转移 | 模型选择看起来像参数，实际改变了正在处理的作品 | `src/app/useWorkspace.ts` 的 `switchFamily`、`draftForIntent` |
| 历史详情和中央结果各自维护选择，浏览历史图 B 时，中央按钮仍可能作用于上一次结果 A | 用户无法从视觉焦点判断操作对象 | `src/components/HistoryPanel.tsx` 的 `detailId`，`src/App.tsx` 的 `useResult` |
| 在历史页点击新建，草稿已重置，但仍留在历史页 | 有副作用却没有可见的任务切换 | `src/App.tsx` 的新建按钮 |
| 生成张数存在控件本地状态，切去历史再返回会恢复为 1 | 已设置的批量任务意图丢失 | `src/workspaces/shared/Controls.tsx` 的 `repeatCount` |
| 批次逐张存入历史，却在整个批次结束后才向当前结果区发布 | 第一张已经可用，用户仍无法在当前结果区挑图继续编辑 | `src/app/useGenerationQueue.ts` 的循环和 `onResult` |
| 单一队列按顺序执行完整批次；正在运行的批次没有停止后续张数的入口 | 挑到满意结果后，剩余生成会继续占用等待时间与预算 | `src/app/useGenerationQueue.ts` 的队列调度 |

以上前五项已用模拟交互复现。各路由参数记忆、不可变生成快照、撤销、逐张落盘和失败不自动重试都是应保留的机制。草稿按家族隔离的结构则应重写，让正在创作的内容围绕任务保存，避免模型切换变成隐蔽的作品切换。

## 按任务决定中央区域

| 当前任务 | 中央区域 | 主要操作 |
| --- | --- | --- |
| 普通生成，包含有参考图的生成 | 按批次排列的候选结果网格；空状态提示输入和生成 | 查看大图、挑选、下载、添加为参考、开始编辑 |
| 编辑图片 | 主图工作区和必要的编辑工具；结果可与提交时原图对照 | 指定主图、描述修改、绘制模型支持的蒙版、继续编辑 |
| 需要包围盒的生成 | 明确开启的区域构图画布 | 绘制和调整输出区域、绑定参考图来源区域 |

画布的出现由任务能力决定。选择 FLUX 本身不应强制占用画布；进入需要区域的路由或开启区域构图时，再给出画框入口。退出区域构图要保留草稿中的区域，并明确它们是否仍会发送，不能出现画布隐藏但区域继续悄悄生效的状态。Runware FLUX 文生图当前要求放置区域，应在选择该路由时直接说明并进入区域构图。

主导航建议使用生成、编辑、图库。模型家族、版本和供应商归入当前任务的设置区。图库负责找图和复用，生成记录负责提示词、参数、费用与任务状态；生成记录降为任务详情入口，不再承担图片管理。编辑页保留可折叠的近期生成面板；普通生成页由当前任务的结果网格承担浏览功能，不再重复堆叠底部缩略图条。

## 从挑图到跨模型编辑

“用这张图开始编辑”应携带明确的图片身份，进入编辑任务并默认使用最近的编辑模型。选中图片成为第一张主图，用户可以直接更换编辑模型。源生成任务、原批次和正在执行的请求保持可返回，不要求用户先到某个模型页导入图片。

新的草稿边界是创作任务。任务持有提示词、主图、参考图、参考用途和编辑状态；模型与供应商选择影响参数和可用能力，不再切换整份内容。每个路由的参数仍独立记忆。模型切换可撤销；不支持的蒙版或区域先保留并明确提示处理方式，不能默默丢弃或发送。进入已有编辑任务并替换主图时，显示待替换内容并允许取消；主图更换必须同步清除旧主图蒙版和来源区域。其他参考素材应明确选择沿用，避免混入无关旧素材。

| 状态归属 | 保存内容 |
| --- | --- |
| 图库资产 | 图片文件、缩略图、尺寸、名称和来源 |
| 创作任务 | 提示词、主图、参考图及用途、蒙版、区域、生成张数、撤销记录 |
| 模型路由设置 | 当前模型和供应商、各组合的参数记忆及能力限制 |
| 生成记录 | 不可变请求快照、输入副本、任务状态、费用和输出图片 ID |

批次结果应逐张进入结果网格，显示实际已完成张数和失败项。支持“停止后续生成”：当前已发出的请求继续接收结果，未发出的请求取消。它不能被标成远程请求已取消。让用户挑中结果后停止剩余候选生成，即可避免编辑请求长期排在该批次之后；进一步的队列优先级应单独设计。

## 图库作为图片入口

图库是一份持久的图片集合。图片从本机导入时复制到受管图库目录；剪贴板图片编码后存入同一目录；每一张生成结果完成后立即入库，包括部分失败批次中的成功图片。用户可以先整理图库，再选择图片开始创作，不必先打开某个模型工作区。导入到当前任务也要先入库再加入工作副本。现有 URL 导入若继续保留，应遵循相同规则。

视觉参考 iOS 相册的等尺寸紧凑网格：图片占据主体，间距小，默认按时间倒序，可按日期分组。常态不在每张图下堆叠模型、提示词和按钮；通过全部、生成、导入做轻量筛选。缩略图允许填充裁切，打开大图后完整显示原始比例。宽屏和窄屏自适应列数，长列表使用缩略图和分段加载，避免一次读取所有原图。

单击图片进入大图详情，明确提供“开始编辑”“添加为参考图”“另存为”和“删除”。生成图片可以展开其生成记录。进入选择模式后单击才代表勾选；底部操作栏显示选中数量、添加为参考图和删除，避免浏览与批量操作混用。返回入口持续可见，并恢复先前网格位置。

“导入到图库”只新增资产；“添加为参考图”才修改任务。生成和编辑页的素材区都提供“从图库选择”，以抽屉或弹层复用同一网格，支持多选、预览、已选标记和剩余参考图名额，确认后按选择顺序追加到当前任务。无需离开工作区寻找历史，也不重复复制一份图库资产。设为主图只选一张，并展示目标编辑模型。图库独立页面也支持将所选图片添加为当前任务的参考素材。此前“从历史导入生成图片”的需求由图库统一承接，不再新增另一套历史选图器。

### 图片和生成记录的关系

目前 `commands::import_image` 与 `clipboard_image` 返回图片数据供草稿使用；`HistoryStore` 在 `history/images/<任务 ID>/` 下保存输入、蒙版和生成结果。`HistoryStore::delete` 仅移除索引条目，不删除目录中的文件。图库需要独立存储契约，不能直接把历史列表换成网格。

建议图片记录包含稳定的 `assetId`、受管原图和缩略图路径、尺寸、格式、创建时间、原始名称与来源类型。生成图片另关联任务 ID、请求 ID 和该请求内的结果序号。主图、风格参考等角色属于当前任务中的使用关系，同一图片可在不同任务中承担不同角色。

图库管理生成结果的原图文件；生成记录通过图片 ID 引用结果，并保留生成参数。生成记录仍独立保存提交时的输入和蒙版快照，以维持请求追溯语义。正在编辑的草稿使用独立工作副本，不把图库中的文件当作可被原地改写的编辑文件。

### 删除和保存规则

| 动作 | 文件与状态变化 |
| --- | --- |
| 删除图库图片 | 删除对应受管原图、缩略图和图库数据项；本机导入源文件不受影响 |
| 删除已关联生成记录的图库图片 | 记录保留参数和任务信息，结果位置显示图片已删除，停用打开和导出；不得留下破图或偷偷恢复图片 |
| 删除正在被草稿使用的图库图片 | 当前工作副本继续可用，标记来源已从图库删除；不自动将工作副本重新入库 |
| 删除生成记录 | 不连带删除图库图片；需要同时清理图片时，通过明确的图库删除操作完成 |
| 生成完成但入库失败 | 保留可见结果并提示重试保存；不能重试付费生成，也不能把磁盘保存失败误报成模型生成失败 |

图库批量删除应明确展示删除数量，并在文件删除成功后才报告完成。只接受图片 ID，后端按索引解析受管路径，不接受前端传来的任意删除路径。文件与索引更新需要可恢复的事务步骤；失败时保留可重试状态，不能先删记录后留下无人管理的文件。

入库以任务 ID、请求 ID 和结果序号防止重复保存，生成队列刷新或重试落盘不会产生重复图片。删除标记属于内部保存日志，避免后续同一批次刷新把用户已删除的结果重新创建；图库数据项本身仍按用户要求移除。

直接定义新的图库、任务和生成记录格式，不为旧历史目录编写迁移器或双格式兼容层，也不从旧目录扫描恢复图库内容。新版本自身仍需保证保存、删除、重启恢复与索引一致性；不要求旧数据兼容并不改变这些运行时要求。图库已按上述约定实现，新数据使用 `workbench/gallery/`，不操作本机旧目录中的图片。

## 当前任务中的素材角色

现有编辑主图已有强调色边框与文字标识，但整个卡片的强调还不足以让缩略图角色一眼可辨。建议主图缩略图使用固定主图色框并标注“主图”，其他参考图使用另一种参考色框和用途标签。选中、悬停、拖动使用独立的选中标记，避免同一种颜色同时表示“主图”和“当前选中”。明暗主题和色觉差异下，文字标识仍应可读。

普通生成没有主图，素材都作为参考；编辑只能有一张主图，固定显示在最前面并与 API 输入第一张保持一致。风格、主体、构图等用途继续编译为提示词，不制造供应商未支持的角色字段。

图库预览不改变当前草稿，点击使用才产生一次可撤销操作。结果页、图库和生成记录详情的“添加为参考图”应调用同一条素材使用逻辑，统一检查图片数量、主图顺序和蒙版约束。图库负责保存，素材列表负责当前任务中的用途，两者不再混为同一状态。

## API 字段与控制感

当前共享模型目录已经能按路由生成控件和过滤请求。下一步应补齐能力表达和操作反馈，而不是把所有字段直接铺成一张长表。

| 控件层级 | 内容与行为 |
| --- | --- |
| 常用 | 模型与供应商、提示词、比例或尺寸、分辨率、生成张数 |
| 按任务出现 | 主图、参考用途、来源和目标包围盒、蒙版、透明背景 |
| 高级 | 种子、质量、输出格式与压缩、扩写、审核级别，以及当前路由实际支持的思考和搜索控制 |
| 请求检查 | 展示最终发送值、供应商默认值与参数调整；账户、缓存、请求标识等传输信息不占据创作主界面 |

每个字段都需要明确默认、自动、随机和显式值的区别。切换模型时保留原路由参数，主动说明不兼容值如何处理；错误显示在对应控件附近，提交前汇总定位。有关联的选项一起变化，例如 PNG 不发送有损压缩参数，参考图存在时 Qwen 扩写方式受限。控件说明只解释当前约束。

目前可确认的缺口包括：

- `changeRoute` 会归一化不兼容值，但界面未显示调整摘要，现有架构文档的承诺与实现不一致。
- FLUX 对非主图来源区域缺少完整的可视编辑入口；只发送正确坐标还不等于用户能够精确控制。应允许在对应参考图上画来源框，并提供数值微调。
- 目录的字段说明未统一显示，提示词输入上限固定为 32000，与部分路由的更低上限不一致。
- Google 的思考级别、搜索工具和多轮对话仍未接入。搜索需要同时设计结果来源展示，不能只增加一个开关后丢弃返回的来源信息。[Google 图像生成文档](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)。

Nano Banana 2.1 本轮接入 OpenRouter 与 Google 的单次生成和参考图编辑：1K/2K/4K、14 种比例、最多 14 张参考图；Google 另有自动比例。新版不支持 512；旧版模型与设置继续保留。OpenRouter 每次请求一张，由应用队列实现多张生成。[OpenRouter 模型目录](https://openrouter.ai/api/v1/images/models)、[Google 模型说明](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1)。

## 实施顺序与验收场景

先按新的资产与任务结构建立图库的入库、删除和生成记录关联，再交付网格浏览、本机及剪贴板导入、生成结果逐张入库。随后打通工作区内的图库多选、模型切换时保留创作内容，以及主图与参考图角色。同期消除新建不返回任务页、生成张数丢失等操作断点。最后按三种任务重排中央区域，补齐参数反馈和各路由能力。旧格式兼容和数据迁移不在迭代范围内。

核心验收场景是生成 8 张图，在前 3 张完成时从结果区或图库挑选一张，用另一模型开始编辑，再从图库追加两张参考图。过程中应能清楚辨认主图与参考用途，停止未发送的候选请求，返回原批次，撤销主图替换，并在切回模型后恢复该路由参数。删除图库图片后重启应用，文件和图库项均不再存在，生成记录保留且不重新恢复图片，本机导入源文件仍存在。普通生成不出现无用途画布；编辑和区域构图保留足够工作面积。小窗口中缩略图、返回入口和面板展开入口均可达。
